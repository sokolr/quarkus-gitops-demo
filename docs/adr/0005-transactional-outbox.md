# ADR 0005: transactional outbox у Service B

## Рішення

- Flyway V4 додає таблицю `outbox_event` до тієї самої PostgreSQL, що зберігає
  `service_message`. Код B робить обидві вставки/оновлення в одній транзакції.
- Планувальник B обирає непередані рядки через `FOR UPDATE SKIP LOCKED`, щоб
  два Pod не працювали над одним рядком одночасно. Він надсилає raw JSON через
  AWS SDK v2 і позначає рядок надісланим лише після відповіді SNS.
- Якщо SNS недоступний, транзакція publisher відкочується; подія лишається в
  outbox. Якщо SNS прийняв її, але commit позначки не відбувся, можливий дубль.
  Наступний consumer має обробляти дублікати без повторних бізнес-ефектів.

## Межі поточного етапу

Старий B, який ще працює під час першого rollout V4, не пише в outbox. Це
перехідне вікно належить закрити до підсумкової демонстрації AC7. Локальне
збереження стану MiniStack не є доказом довговічності AWS SNS; це теж буде
окремо зазначено в підсумковій перевірці.
